# Table 2 Data and Evaluation

This note answers the four data and evaluation questions needed to reproduce
the LegalGraphRAG results in Table 2. Baseline implementations are outside the
scope of this repository.

## 1. Retrieval corpus

`datas/cases_with_feature.json` is a small demonstration corpus. It is not the
retrieval corpus used for Table 2.

The complete retrieval corpus is included at:

```text
datas/main_experiment/cases_with_feature_big.json
```

It contains 14,049 feature-annotated cases.

## 2. Corpus IDs and sources

The full source manifest is
`datas/main_experiment/corpus_sources.json`. Case IDs are sequential strings
assigned after concatenating the processed sources in this order:

| Case IDs | Count | Dataset | Source split |
| --- | ---: | --- | --- |
| 1-3512 | 3,512 | [CAIL](https://github.com/thunlp/CAIL) | `test.json` |
| 3513-9264 | 5,752 | [JuDGE](https://github.com/oneal2000/JuDGE) | `filtered_ext_all.jsonl` |
| 9265-14049 | 4,785 | [CMDL](https://github.com/littlebowlnju/CMDL) | `train_small.jsonl` |

Some records with visibly incomplete judgment information were removed
manually during the original processing. The released 14,049-case file is the
authoritative processed corpus.

[LeCaRDv2](https://github.com/THUIR/LeCaRDv2) was also used as a reference
during manual corpus review, and a small amount of its data was incorporated
as supplementary material. These supplementary records were not separately
tagged with source IDs in the processed corpus.

## 3. Construction scripts

`scripts/sample_source_cases.py` implements the CAIL and CMDL per-charge
sampling and the CMDL per-defendant split. The historical boundary is
`count < limit`; use `--boundary historical` to preserve it. The sampling
target is selected by changing `--input` and `--role`:

```bash
# Retrieval-corpus samples: use the source training/corpus split and quota 20.
python scripts/sample_source_cases.py \
  --dataset CAIL --role corpus --input raw/CAIL/test.json \
  --max-per-charge 20 --boundary historical --output work/cail.json

python scripts/sample_source_cases.py \
  --dataset CMDL --role corpus --input raw/CMDL/train_small.jsonl \
  --max-per-charge 20 --boundary historical --output work/cmdl.json

# Evaluation samples: select the corresponding held-out source split.
python scripts/sample_source_cases.py \
  --dataset CAIL --role test --input raw/CAIL/final_test.json \
  --max-per-charge 5 --boundary historical \
  --output work/crime_data_CAIL_small.json

python scripts/sample_source_cases.py \
  --dataset CMDL --role test --input raw/CMDL/test_small.jsonl \
  --max-per-charge 10 --boundary historical \
  --output work/crime_data_CMDL_small.json
```

CAIL corpus and test records come from different official CAIL subsets; CMDL
uses `train_small.jsonl` for retrieval and `test_small.jsonl` for evaluation.
The general intended test quota was 5, but the released 1,374-record CMDL test
set was generated by the historical invocation with a quota of 10.
`--exclude-test` additionally removes normalized exact-fact overlaps when
building a new corpus.

After feature extraction, merge the three processed source files with:

```bash
python scripts/merge_retrieval_corpus.py \
  --cail work/CAIL/cases_with_feature_big.json \
  --judge work/JuDGE/cases_with_feature_big.json \
  --cmdl work/CMDL/cases_with_feature_big.json \
  --exclude-test datas/main_experiment/crime_data_CAIL_small.json \
  --exclude-test datas/main_experiment/crime_data_CMDL_small.json \
  --verify-paper-counts \
  --output work/cases_with_feature_big.json \
  --manifest-output work/corpus_sources.json
```

Both scripts provide an optional `--deduplicate` flag for exact duplicate
records. It is disabled for historical reproduction because the released
corpus retains such records. Facts must not be used alone as a deduplication
key: CMDL judgments with multiple defendants are split into one record per
defendant, so repeated facts are expected.

## 4. Table 2 evaluation

The repository includes both processed evaluation sets:

```text
datas/main_experiment/crime_data_CAIL_small.json   # 568 cases
datas/main_experiment/crime_data_CMDL_small.json   # 1,374 defendant records
```

Evaluate a generated result file with:

```bash
python evaluation/evaluate_results.py \
  --results outputs/main_experiment/CAIL/qwen3_results_combined.json

python evaluation/evaluate_results.py \
  --results outputs/main_experiment/CMDL/qwen3_results_combined.json
```

The evaluator accepts current `judge_result.charge_name` predictions and the
legacy Table 2 `judge_res[].crime` format. Accuracy is exact match and Micro-F1
is aggregated over all labels. Each CMDL row represents one defendant and is
scored once; therefore its `judgment_count` is 1,374.

As a regression check, evaluating the archived Table 2 Qwen3 CMDL output gives
Accuracy `0.5756914119359534` and Micro-F1 `0.617426820966644`.
